## ПОСТАНОВКА ЗАДАЧІ
Під час виконання практичної роботи необхідно:
1. Побудувати для задачі лінійного програмування $(Z)$ (див. практичну роботу № 1.В) двоїсту задачу лінійного програмування $(W)$.
2. Розробити програму, за допомогою якої можна розв'язати пару взаємно двоїстих задач $(Z, W)$ симплекс-методом.
3. Розв'язати побудовану двоїсту задачу $(W)$ безпосередньо шляхом підставлення її симплекс-таблиці в практичну роботу № 1.В.
4. Порівняти результати (оптимальні розв'язки), які було отримано під час розв'язання задачі $W$ безпосередньо і шляхом розв'язання пари двоїстих задач.
5. Побудувати для задачі лінійного програмування двоїсту задачу й розв'язати пару взаємно двоїстих задач графічно.

## ВИКОНАННЯ РОБОТИ
Для виконання практичної роботи було розроблено консольний застосунок мовою C#. Програма забезпечує повний цикл обчислень відповідно до алгоритмів, наведених у методичних вказівках, включаючи роботу з двоїстими задачами.

Для розв’язання пари взаємно двоїстих задач застосовано спільну симплекс-таблицю з подвійними мітками. Зліва розташовані базисні змінні прямої задачі ($y$) та двоїстої ($u$), зверху — вільні змінні прямої ($x$) та двоїстої ($v$). Після кожного кроку модифікованих жорданових виключень (МЖВ) мітки обмінюються місцями одночасно для обох задач. Розв’язок прямої задачі ($X$) зчитується з останнього стовпця, а розв’язок двоїстої задачі ($U$) — з останнього рядка.

Також використано алгоритм побудови двоїстої задачі за правилами переходу: якщо пряма задача на максимум, то двоїста — на мінімум; обмеженням-нерівностям типу $\le$ відповідають невід’ємні змінні двоїстої задачі; невід’ємним змінним прямої задачі відповідають обмеження-нерівності типу $\ge$ двоїстої задачі.

### Структура програми (Архітектура проєкту)
Архітектуру програмного рішення проілюстровано в структурі коду проєкту. До основних компонентів системи відносяться:
* `Matrix` — клас для роботи з матрицями, реалізації кроків МЖВ (`JordanExclude`) та керування подвійними мітками стовпців і рядків (`ColMarkersDual`, `RowMarkersDual`).
* `InequalitySystem` та `Inequality` — класи для представлення й трансформації системи обмежень та окремих нерівностей.
* `GoalFunction` — клас, що відповідає за цільову функцію та її тип (`GoalFunctionType`).
* `ComputationResult` — клас для акумуляції кроків обчислень та генерації фінального протоколу.
* `InputHandler` та `ReportPrinter` — статичні класи для забезпечення введення даних користувачем та виведення результатів у консоль.

### Вхідні та вихідні дані
* **Вхідні дані:** кількість змінних ($n=2$), кількість обмежень ($m=2$), коефіцієнти цільової функції та коефіцієнти системи обмежень разом із вільними членами.
* **Вихідні дані:** постановка двоїстої задачі $W$, вхідна спільна симплекс-таблиця, протокол покрокових перетворень МЖВ (пошук опорного та оптимального розв'язків), фінальні вектори розв'язків $X$ та $U$, а також екстремуми функцій $Z(\max)$ та $W(\min)$.

## РЕЗУЛЬТАТИ ТЕСТУВАННЯ

### 1. Розрахунок індивідуального завдання (Варіант 4)
Програма успішно визначила опорний та оптимальний розв'язки для обох задач:
* **Результат для прямої задачі:** $X = (2; 0)$, $\max(Z) = 2.00$.
* **Результат для двоїстої задачі:** $U = (1; 0)$, $\min(W) = 2$.

### 2. Розрахунок тестового прикладу з методичних вказівок
Для верифікації коректності алгоритму було проведено розрахунок тестової задачі із системи обмежень на 4 змінні та 3 обмеження.
* **Результат тесту:** $X = (0; 22; 0; 8)$, $\max(Z) = 36$; $U = (3.5; 0; 1.5)$, $\min(W) = 36$.

### 3. Графічний метод верифікації результатів
Для остаточної перевірки пару взаємно двоїстих задач було розв'язано графічним методом за допомогою калькулятора [Desmos](https://www.desmos.com). Обидва підходи показали ідентичні результати:
* Точка максимуму прямої задачі: $(2, 0)$, значення функції $Z = 2$.
* Точка мінімуму двоїстої задачі: $(1, 0)$, значення функції $W = 2$.
Результати графічного розв'язку повністю збігаються з програмними розрахунками.
